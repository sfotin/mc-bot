# Правила работы с проектом mc-bot
- Перед любой работой читай BOT.md. Не перечитывай весь код, если ответ есть в BOT.md.
- Любое изменение кода, формата схем, команд, флагов CLI или config.js → в том же коммите обнови соответствующие разделы BOT.md и добавь строку в «Журнал изменений» (дата + что изменилось). В шапке BOT.md указывай хеш ПРЕДЫДУЩЕГО коммита (родителя) в формате: «по состоянию коммита <хеш> + изменения следующего коммита (<краткое описание>)». `commit --amend` для обновления хеша не использовать.
- Если BOT.md расходится с кодом — прав код, исправь BOT.md.
- Исправленные проблемы убирай из раздела «Известные проблемы и TODO», новые — добавляй.
- После изменений делай commit и push в origin master.
- CITY.md — документ проекта города: участок, зонирование, инженерные правила для зданий и промзоны. Читай его перед работой над схемами города. Любое изменение схем города, генплана или инженерных правил → обнови CITY.md и добавь строку в его «Журнал изменений» в том же коммите.
- mineflayer не работает с нашим сервером (не разбирает чанки). Не предлагай и не реализуй решения на mineflayer. Для команд — только index-cmd.js (minecraft-protocol без модели мира).
- Перед предложением нового подхода проверь раздел «Опыт» в BOT.md — не повторяй то, что уже пробовали и отвергли.
- .env пользователя не трогать: не удалять, не перезаписывать, не коммитить. Для тестов — отдельный .env.test.
