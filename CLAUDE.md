# Правила работы с проектом mc-bot
- Все сообщения пользователю — только на русском (отчёты, вопросы, комментарии). Код, имена файлов, команды, коммиты — как есть.
- BOT.md, CITY.md, DECOR.md не читать целиком: сначала `grep -n "^#" <файл>` (оглавление), затем открывать только нужные разделы. BOT.md — перед работой с кодом бота, CITY.md — перед схемами города, DECOR.md — перед декором.
- Если документ расходится с кодом — прав код, документ исправить.
- Любое изменение кода / формата схем / CLI-флагов / config.js / схем города / генплана / инженерных правил / декора → в том же коммите обновить только затронутые разделы соответствующего документа (BOT.md / CITY.md / DECOR.md) и добавить одну строку в его «Журнал изменений». Остальные разделы не переписывать.
- Шапка BOT.md — не хеш коммита, а фиксированная строка «актуальное состояние — последний коммит в master»; не поддерживать хеш, `commit --amend` ради этого не делать.
- Регрессию по всем схемам (`schemas/`) гонять только при изменении lib/fill-plan.js или index-cmd.js. В остальных случаях — проверка только затронутой схемы/генератора.
- Если пользователь приложил готовые файлы и ожидаемые числа (записи/команды/материалы) — не переписывать генераторы сверх необходимого: перенос файлов, правка параметров путей, сверка чисел, коммит.
- Исправленные проблемы убирать из «Известные проблемы и TODO» в BOT.md, новые — добавлять.
- После изменений — commit и push в origin master.
- mineflayer не работает с нашим сервером (не разбирает чанки). Не предлагать и не реализовывать решения на mineflayer. Команды — только через index-cmd.js (minecraft-protocol без модели мира).
- Перед новым подходом проверить раздел «Опыт» в BOT.md — не повторять уже отвергнутое.
- .env пользователя не трогать (не удалять, не перезаписывать, не коммитить). Для тестов — отдельный .env.test.
- Отчёт по рутинным заданиям — коротко: хеш коммита, совпали ли ожидаемые числа, что не сделано.
