# WORKFLOW — как идёт работа над «МС городом»

Цель — меньше расхода лимитов: чат проектирует и собирает пакет, Claude Code только применяет его, владелец строит сам.

## 1. Роли

- **Чат (Claude, проект «МС город»)** — план района, генераторы, схемы, проверки, превью, **пакет**. Документы (BOT.md, CITY.md, HANDOFF.md, DECOR.md) правит сам и кладёт в пакет целиком.
- **Claude Code** — запускает одну команду `python tools/apply_pack.py --clean` и присылает хвост вывода. Ничего не читает, не правит и не проверяет сверх этого. Модель — подешевле (Haiku / Sonnet с низким усилием).
- **Владелец (Serg)** — запускает `builds/build-<порция>.cmd` при работающем сервере, смотрит результат, присылает замечания и скриншоты.

## 2. Цикл района

1. **Новый чат на район.** Клонировать репозиторий, прочитать `docs/HANDOFF.md` и этот файл; CITY.md / BOT.md / DECOR.md / код — только нужные места (`grep -n "^#"`, затем разделы).
2. **План** — `tools/city/plan_<район>_v1.py` → картинка + текст раздела CITY.md; схемы — после утверждения владельцем.
3. **Порции** — крупные, несколько объектов: генераторы `tools/city/gen_<район>_<этап>.py`, все проверки (BOT.md §12, HANDOFF §4), одно превью на порцию, пакет.
4. **Исправления по замечаниям** — v2 генератора + `--fix-from <построенная схема>` → `<район>-<этап>-fix-N.json` (только отличия; ручные правки владельца — `USER_EDITS`, в исправления не входят).
5. **Отметки «построено»** (`BUILT` в `world_model.py`, BOT.md §9, CITY.md, HANDOFF) — в следующем пакете, отдельным пакетом не отправлять.
6. **Закрытие района** — план v2 «как построено» (`plan_<район>_v2.py`), HANDOFF §1/§5/§6, в конце ответа — стартовый промпт для нового чата следующего района.

## 3. Пакет

Файл `mc-bot-pack-<район>-<N>.zip`. Владелец кладёт его **в корень папки `mc-bot`**; имя — любое вида `mc-bot-pack-*.zip` (в т.ч. «… (1).zip» от браузера), берётся самый свежий. Внутри:

- `files/` — все новые и изменённые файлы **целиком**, по путям репозитория (генераторы, схемы, превью, документы, `builds/*.cmd`);
- `docs.patch` — те же изменения документов в виде `git diff` (только для просмотра);
- `BASE` — коммит, от которого собран пакет; `COMMIT_MSG` — сообщение коммита;
- `apply.sh` в пакет **не кладётся** — применяет `tools/apply_pack.py` (Python + git, одинаково в Windows и Linux): находит свежий архив в корне, распаковывает в `.pack` (старую удаляет), проверяет BASE = HEAD и чистое дерево, копирует `files/`, запускает `tools/city/verify.py`, при «verify: все OK» — `git add` явного списка, commit (`COMMIT_MSG`), push, удаляет `.pack` и архив. При ошибке — «СТОП: …» и откат, ничего не коммитится. `--clean` — сначала откатить незакоммиченные изменения отслеживаемых файлов (остатки неудачной попытки), `--no-push` — без push.

## 4. Промпт для Claude Code (шаблон)

```
В корне mc-bot лежит пакет mc-bot-pack-*.zip. Выполни одну команду:
python tools/apply_pack.py --clean
Ничего не читай и не правь сам. Пришли последние 15 строк вывода.
```

## 5. Проверки

- `tools/city/verify.py` — единая проверка: все генераторы из `REGISTRY` запускаются во временную папку и сверяются со `schemas/`, разбирается вывод их проверок. Итог — «verify: все OK». **Новый генератор района добавляется в `REGISTRY` в том же пакете.**
- Генератор уже построенной схемы берёт `World(built_before('<своя схема>.json'))`.
- Проверки генератора (опоры, вода, порядок, проходимость без прыжков, скамейки, висящие над мощением, подходы к дверям, кровля каньона, резерв трасс, негативные прогоны) — в выводе генератора; в ответе владельцу — одной строкой.

## 6. Постройка

`builds/build-<порция>.cmd` — команды `node index-cmd.js <схема> <origin>` по порядку, в конце `pause`. Владелец запускает двойным щелчком из папки `builds` при работающем сервере. Claude Code для постройки не используется.

## 7. Экономия

- Не читать документы целиком; не перечитывать то, что уже в контексте.
- Одно превью на порцию, короткие ответы (что сделано, проверки одной строкой, пакет, промпт, команды).
- Длинный чат дорог (каждое сообщение пересылает всю историю) — новый чат на каждый район.
